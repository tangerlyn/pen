# PENGWYN 개발 변경 기록

이 문서는 PENGWYN의 완료된 수정사항과 확인된 후속 작업을 한 파일에서 날짜별로 관리한다.

작성 규칙:

- 실제 작업 날짜를 `YYYY-MM-DD` 제목으로 사용한다.
- 날짜 안에서 `수정사항`과 `확인된 문제 및 후속 작업`을 분리한다.
- 각 항목은 1번부터 순서대로 기록하고 상태를 `완료`, `진행 중`, `미완료`로 표시한다.
- 보안 키, 토큰, 비밀번호, 개인정보의 실제 값은 이 문서에 복사하지 않는다.
- 기능을 변경한 날에는 관련 테스트와 검증 결과도 함께 기록한다.

## 2026-08-27

### 수정사항

1. **검색 무한 스크롤 구현 — 완료**
   - 리뷰와 커뮤니티 결과의 커서, 로딩, 종료 상태를 독립적으로 관리하도록 변경했다.
   - 후보 페이지가 모두 오탐이면 실제 일치 결과를 찾거나 후보가 끝날 때까지 다음 페이지를 조회한다.
   - 중복 항목 제거, 중복 요청 방지, 누적 결과 전체 재정렬, 이전 검색 요청의 늦은 응답 무시 처리를 추가했다.
   - 통합 검색에서 리뷰 가로 목록과 커뮤니티 세로 목록이 각각 다음 페이지를 요청하도록 연결했다.
   - 관련 파일: `lib/data/repositories/search_repository.dart`, `lib/features/search/providers/search_provider.dart`, `lib/features/search/screens/search_screen.dart`, `docs/search.md`

2. **채팅 기능 제거 — 완료**
   - 채팅 화면, Provider, 모델, 저장소, 라우트, 이미지 업로드 함수, 알림 설정과 상수를 제거했다.
   - 댓글을 나타내는 `chat_bubble` 아이콘과 댓글·답글 기능은 유지했다.

3. **앱 표시 이름 통일 — 완료**
   - 공식 표시 이름을 `펜귄(PENGWYN)`으로 정리하고 한국어 축약명 `펜귄`, 영문명 `PENGWYN`을 상수화했다.
   - Flutter 앱 클래스명을 `PengwynApp`으로 변경했다.
   - Firebase 프로젝트 ID, Android application ID, iOS bundle ID, URL scheme, 알림 채널 ID 등 기존 `nibpen` 기술 식별자는 설치·로그인 호환성을 위해 유지했다.

4. **대형 화면 기능 단위 분리 — 완료**
   - 잉크북 상세, 게시글 상세, 아카이브, 리뷰 상세, 아카이브 상세 화면에서 표시 위젯을 별도 파일로 분리했다.
   - 잉크북 표시 설정, 아카이브 필터 draft, 댓글·답글 입력 상태를 별도 컨트롤러로 분리했다.
   - 대상 화면 파일 합계는 7,143줄에서 2,907줄로 감소했다.
   - 관련 디렉터리: `lib/features/*/controllers`, `lib/features/*/widgets`, `lib/shared/controllers`

5. **안전 테스트와 iOS QA 추가 — 완료**
   - 검색 페이지네이션, 요청 경합, 중복 제거, 누적 정렬, 필터 draft, 잉크북 설정, 댓글 입력, 브랜드와 알림 상태 테스트를 추가했다.
   - `flutter test` 13개 통과, Functions JavaScript 문법 검사 통과, iOS Simulator 디버그 빌드·설치·실행을 확인했다.
   - iPhone 16e에서 홈, 검색 결과, 아카이브, 아카이브 상세, 리뷰 상세, 게시글 상세, 잉크북 상세 화면을 캡처해 독립 시각/CJK 검토를 통과했다.
   - Android 빌드와 테스트는 사용자 요청에 따라 실행하지 않았다.

6. **디자인 시스템 문서화 — 완료**
   - 기존 색상, 글꼴, 간격, 컴포넌트, 접근성 기준과 화면 분리 원칙을 루트 `DESIGN.md`에 기록했다.

### 확인된 문제 및 후속 작업

1. **소셜 로그인 인증 구조 교체 — 미완료 / 최우선**
   - 현재 카카오·네이버 로그인은 소셜 사용자 ID와 클라이언트에 포함된 고정 salt로 Firebase 이메일/비밀번호를 결정적으로 생성한다.
   - 앱 바이너리에서 salt와 계산 로직을 추출할 수 있으므로 이 값은 비밀로 사용할 수 없다. 소셜 사용자 ID까지 알게 된 공격자는 해당 Firebase 자격 증명을 재현할 가능성이 있다.
   - 클라이언트가 소셜 토큰을 서버에서 검증하지 않은 채 `_firebaseEmailAuth`를 호출하며, 로그인 실패 시 같은 자격 증명으로 계정 생성까지 시도한다.
   - 권장 수정: 신뢰할 수 있는 서버 또는 Cloud Functions에서 카카오·네이버 토큰을 공급자 서버에 검증하고, Firebase Admin SDK의 custom token을 발급한 뒤 앱은 `signInWithCustomToken`을 사용한다.
   - 기존 사용자 UID와 Firestore 문서를 보존하는 계정 연결·마이그레이션 설계가 먼저 필요하다. 로그인 코드만 즉시 교체하면 기존 사용자가 새 계정으로 분리될 수 있다.
   - 관련 파일: `lib/data/services/auth_service.dart`, `lib/core/constants/app_secrets.dart`

2. **클라이언트 비밀값과 토큰 로그 제거 — 미완료 / 최우선**
   - 네이버 client secret과 인증용 salt가 클라이언트 소스에 포함되어 있어 앱에서 추출할 수 있다.
   - 카카오 access token을 `debugPrint`로 출력하는 코드가 로그인과 재인증 경로에 남아 있다.
   - 권장 수정: 네이버 secret을 회전하고 서버로 이동하며, 토큰 로그를 즉시 제거한다. 카카오 Native App Key처럼 클라이언트 식별자로 사용되는 값은 비밀로 간주하기보다 플랫폼·bundle 제한을 적용한다.

3. **Firestore·Storage 권한 규칙 강화 — 미완료 / 최우선**
   - 다른 사용자의 프로필 정보, 카운터, 공용 카탈로그와 업로드 파일을 과도하게 읽거나 수정할 수 있는 규칙이 이전 검토에서 확인됐다.
   - 소유권 검증, 변경 가능한 필드 제한, 서버 전용 카운터 갱신과 Rules Emulator 기반 보안 테스트가 필요하다.

4. **정적 분석 진단 정리 — 미완료**
   - `flutter analyze`에 오류는 없지만 기존 경고 1건과 정보 진단을 포함해 111건이 남아 있다.
   - 비동기 이후 `BuildContext` 사용, deprecated API, 불필요한 cast/import, 스타일 진단을 기능별로 정리해야 한다.

5. **남은 대형 화면 추가 분리 — 미완료**
   - 1차 분리 후에도 잉크북 상세, 게시글 상세, 리뷰 상세 facade에는 화면 조립과 액션 로직이 비교적 많이 남아 있다.
   - 동작 테스트를 유지하면서 저장·내보내기, 게시글 액션, 리뷰 액션을 별도 서비스/컨트롤러로 추가 분리할 수 있다.

6. **접근성 부채 수정 — 미완료**
   - 이전 QA에서 최대 글자 크기의 하단 탐색 overflow와 낮은 비선택 탐색 대비가 확인됐다.
   - 고정 높이 탐색 영역과 앱바를 글자 크기에 맞게 조정하고 최대 Dynamic Type에서 다시 검증해야 한다.
